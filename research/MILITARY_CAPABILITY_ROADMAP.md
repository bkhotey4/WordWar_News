# Discord 公開軍事情報能力擴充方案

狀態：這是新增功能設計，未宣稱已接入下列新來源或啟用預測模型。已核對專案採集、研究、衛星目錄、發送與健康狀態流程。

## 一、目前缺口

- `src/osint_crawler.js` 的 `fetchMNDMilitaryActivity` 查詢 Google News；不能把搜尋結果當國防部原始數據。
- `src/research_reports.js` 的自動正文採集集中在烏克蘭軍方來源，外部評估主要靠另行查核匯入；自動研究排程未啟用。
- `src/satellite_stac.js` 查 Sentinel-2 目錄，未建立當期影像與事件之間的來源對應。
- `src/sentry.js` 是關鍵字／應答機代碼待查通知，沒有歷史基準、語意事件合併或經驗證的預測能力。
- JSON 檔適合目前單程序使用；新增多來源、分析排程和通知工作後，需要交易、版本與任務狀態。

## 二、建議架構

公開來源採集 → 原文與觀測保存 → 主張與事件合併 → 查核及版本管理 → 規則與歷史比較 → 中文報導 → Discord／網站

AI 負責翻譯、整理候選主張及撰寫有引用的研究稿；原始數據、日期、規則計算、來源有效性及發送狀態由程式處理。額度不足時仍持續採集和顯示官方原文，分析標示等待，不產生替代假研判。

### 建議資料庫資料表

- `source_documents`：來源 URL、發布與取得時間、內容雜湊、原文版本、發布者及原始出處群組。
- `observations`：觀測／統計期間、數值、單位、地理精度、引用來源、品質與更正版本；未知值為 null。
- `claims`：來源提出的主張、支持與矛盾依據、查核狀態。交戰方聲稱和外部確認分開保存。
- `events`：事件類型、地區、時間範圍、版本及已確認／待確認／更正狀態。
- `imagery_assets`：產品 ID、實際拍攝時間、覆蓋範圍、解析度、雲遮、處理步驟、授權與檔案雜湊。
- `analysis_runs`：模型／規則版本、输入資料版本、完成時間、失敗原因。
- `alerts`、`deliveries`：觸發理由、收件人、成功紀錄、更正通知關聯。

可先遷移至本機 SQLite，保留現有 API；選擇相容本機 Node 版本的驅動或先升級執行環境。不要同時保留兩份可寫的即時數據。

## 三、第一階段：台海原始資料與事件查詢

### 官方來源

- 國防部即時軍事動態：https://www.mnd.gov.tw/newslist/11
- 其他海巡及航行／航空公告：新增前逐一確認官方入口、更新方式與使用條件，不填猜測的 API。
- Google News、PTT、社群只提供候選線索，不能代替官方原始觀測。

### 實作

新增 `src/collectors/taiwan_mnd.js`；逐篇取得官方通報，保存正文及原圖，解析原文的統計起訖期間、共機架次、逾越中線／指定空域架次、艦艇等實際欄位。

欄位缺失、版型改變、圖文不符時標示待覆核，不以零代替，不從昨日或標題補數字。每日總量和臨時單次事件分開；艦／架與艦次／架次保留原始單位。

候選新指令：`/taiwan-status` 官方最新通報；`/taiwan-trend` 歷史趨勢；`/event` 事件時間線；`/sources` 採集狀態。以上尚未註冊。

驗收：解析不同格式與缺值通報；保存統計期間及原圖來源；更正同篇公告時更新受影響的趨勢、稿件與通知，不重複算事件。

## 四、第二階段：戰況研究與來源比對

- 擴充交戰雙方原始公告與外部評估的採集適配器；每個來源獨立健康狀態。
- 建立同地區／同事件的候選合併，經覆核才合併，避免把鄰近但不同事件當成同一件。
- 保存「交戰方聲稱」「外部評估」「可驗證影像」等證據類型；多家轉貼同一公告仍是一個原始出處。
- 戰況稿固定呈現：本次新增消息、相較前稿的變化、支持與矛盾來源、分析、待確認事項。
- 地圖分開顯示已核實的歷史事件及來源主張；無定位證據不畫精確箭頭，無控制區證據不擴張控制面積。
- ACLED 可作歷史事件與回測補充，但它按週發布，不能當分鐘級快訊：https://acleddata.com/methodology/acled-codebook

候選指令：`/war-report region`、`/event-history`、`/corrections`。

## 五、第三階段：實際衛星照片與前後期比較

- 先從現有 STAC 結果選取可用影像資產，實際取得並生成地理參考預覽；逐张保存產品、拍攝時間、范围、授權及處理記錄。
- Sentinel-2 適合光學影像；Sentinel-1 是雷達產品，需要不同處理與解讀流程，不能直接當彩色照片。
- 同區域前後期影像須對齊、檢查雲遮及資料相容性；變化區域只是待查證據，不自動判為戰損或軍事集結。
- NASA FIRMS 可補充熱異常，但工業、農業與自然火源也會出現，不把熱點直接判定為空襲。
- 找不到新影像時顯示「最新可用拍攝時間」與缺圖原因，不以產圖時間包裝即時畫面；不用生成式 AI 補造衛星證據。

資料文件：

- Sentinel-2：https://documentation.dataspace.copernicus.eu/Data/SentinelMissions/Sentinel2.html
- Sentinel-1：https://documentation.dataspace.copernicus.eu/Data/SentinelMissions/Sentinel1.html
- FIRMS 熱源說明：https://wiki.earthdata.nasa.gov/spaces/FIRMS/blog/2025/02/28/425855667/FIRMS%2Bincorporates%2Bstatic%2Bthermal%2Banomalies%2Bdata%2Bto%2Bhelp%2Busers%2Bdifferentiate%2Bbetween%2Bvegetation%2Band%2Bnon%2Bvegetation%2Bfires.

候選指令：`/satellite region`、`/satellite-compare region`。驗收需能從每張圖追溯到實際產品及拍攝日期。

## 六、第四階段：可檢驗的提前提醒

先提供地區層級的活動異常及公開安全資訊變化，不宣稱掌握即時敵軍完整部署或攻擊時間。

- 將官方通報按相同統計期間與單位累積，建立歷史活動基準；缺少資料的日子不當成零。
- 比較最新活動與過去同類觀測，納入已公布演習、假日、季節及來源覆蓋變化等替代解釋。
- 整合公開演習公告、區域管制及正式政府安全通知，保留每個觸發條件與反證。
- 規則設定採版本管理，先在歷史資料上評估通知量、誤報、漏報與提前量，再決定門檻；不先填武斷的「開戰機率」。
- 初期通知分為「新線索」「統計異常待查」「已有佐證事件」「更正／解除」。事件確認程度與異常程度分開。
- 先以觀察模式保存候選提醒，覆核有用後再開放自動推送，附原始來源、觀測時間及規則理由。

候選指令：`/watch-region`、`/alert-preferences`、`/alert-explain`、`/analysis-health`。

## 七、實作順序與完成定義

1. 官方台海來源 + 交易資料庫 + 單位／統計期間驗證。
2. 事件版本 + 來源關係 + 更正通知。
3. 實際影像取得 + 原始產品追溯 + Discord 圖片展示。
4. 地區異常觀察模式 + 歷史回測 + 分級通知。
5. 啟用並實測研究排程；確認最近成功、下一次執行與額度失敗處理。

採集频率依官方來源更新節奏、限流與條件設定；AI 只分析有意義的增量變化。啟用排程或登入新服務需以實際成功結果確認，不能只改設定檔就宣布完成。
