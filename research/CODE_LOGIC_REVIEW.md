# 程式邏輯檢查與功能建議

檢查範圍：資料採集、原文研究、稿件驗證、網站/API、Discord 指令、預警與早晚簡報。此文件記錄已確認的問題，不將程式測試視為新聞真實性的保證。

## 已修正

| 問題 | 原因與修正 |
| --- | --- |
| 重複刷新互相覆寫 | 同一程序內採集共用正在執行的工作；原文採集完成時合併期間匯入的研究參考，使用唯一暫存檔。 |
| 舊資料可用未引用的新來源刷新日期 | 每份來源必須在段落中實際引用，不能把未引用的新文章掛進稿件以延長時效。 |
| 不合法引用造成例外或推播拒絕 | 限制引用型別、重複引用、段落標籤、來源數與 Discord 完整訊息長度。 |
| 網站群發與機器人內容不一致 | 群發改用相同 researchDiscordPayload；登入有等待上限、錯誤回應與連線清理。 |
| 航空紀錄過期卻被當作現在 | 不再以本機時間補缺少的 OpenSky 原始時間；個別航跡需有位置與聯絡時間、有效座標及時效。 |
| 重啟造成早晚簡報重複發送 | 保存每位收件人的成功紀錄，重啟後略過已成功者；於 08:00–08:59、20:00–20:59 補送及重試。 |
| 預警發送全失敗仍被當作已通知 | 以收件人紀錄重試失敗者，只有全體成功才記錄通知完成；沒有訂閱者時不消耗事件。 |
| 未核實舊內容可直接推送 | 停用舊俄機直接推播腳本；撤除舊專題函式的 sourceBacked 標記。舊專題仍不在有效指令清單內。 |
| 網頁刷新卡住或互相覆蓋 | 資料請求加上時間上限，進行中不啟動另一輪刷新。 |
| 研究來源失敗未顯示 | 原文研究來源加入健康清單，部分文章讀取失敗標示 DEGRADED。 |

另已加入 reportAudit：報導因來源改變、過期或驗證失敗停止展示時，網站會顯示原因。

## 尚有限制

- 自動中文研究排程尚未啟用；Antigravity 接手說明已備妥，但須在實際安裝的應用程式建立並確認排程。
- 目前原文自動採集主要是烏克蘭軍方與軍方媒體；來源數量不等於獨立佐證數。外部評估需另外查閱並匯入。
- 衛星功能目前查詢產品目錄，尚無已核實的本機事件影像或自動變化判讀。
- 預警目前是新聞關鍵字與公開航空訊號的待查通知，不能宣稱能預測戰爭或已確認威脅。
- 本機檔案不提供跨程序交易鎖；避免多個程序同時發布同一資料庫。大量任務或多使用者時應遷移至支援交易的資料庫。
- Discord 已接受訊息後、成功紀錄落盤前若程序崩潰，仍可能重送；目前無法保證嚴格只送一次。
- 對引用的格式與時效驗證不會自動證明段落語意真的受到來源支持，仍需研究者比對原文。
- 舊專題與圖卡產生器尚保留歷史內容，但沒有接回有效報導流程。要恢復功能必須改為讀取有來源的資料。

## 建議新增功能與順序

| 優先 | 功能 | 可交付內容 |
| --- | --- | --- |
| 1 | 事件時間線與更正紀錄 | 同一事件的首次通報、後續佐證、否認與更正；分開事件發生、發布及取得時間。 |
| 1 | 來源關係與相互矛盾追蹤 | 標示原始公告、訪談、轉述和外部評估，按原始出處群組，逐項列出一致與衝突主張。 |
| 1 | 研究任務健康與備援 | 顯示最近成功研究時間、下一次任務與失敗原因；額度不足時保留待查狀態，通知使用者。 |
| 2 | 關注地區與通知偏好 | 選擇台海、俄烏等區域、關鍵字、摘要時段及通知頻率，避免所有新聞都推播。 |
| 2 | 有證據的通知分級 | 分為新線索、已有佐證、更正；每次通知附觸發條件、來源和觀測時間，先量測誤報及漏報。 |
| 2 | 戰況地圖證據層 | 點位連到具日期的原始資料，歷史版本可比較；控制區與推進箭頭須有逐項佐證。 |
| 3 | 衛星前後期比較 | 同區域影像的產品編號、拍攝時間、雲量與可見範圍；先完成取得及來源對應，再加入变化提示與人工覆核。 |

以上功能尚未全部實作；本次實際新增的是報導停止展示原因、原文健康狀態及發送紀錄。
